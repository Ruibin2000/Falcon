### 3.3. Network problems resolved

- **Changing runtime identities:** modem numbers, bearer numbers, WWAN names, IPv4 addresses, and prefixes changed after reconnection. The launcher now discovers them from current IMEI/SIM/APN state instead of reusing historical values.
- **Connected modem with unconfigured host interface:** successful `mmcli --simple-connect` supplied a bearer but did not by itself configure the Laptop interface. The documented sequence installs the actual address/prefix and MTU, raises the WWAN interface, and builds the private server route.
- **Stale addresses and occupied priorities:** old addresses, table routes, and rules caused `Rule priority already occupied` and stale-source lookup failures. The role reset helper discovers and clears the selected role's relevant IPv4 state without requiring a previous session ledger.
- **Ordinary ping selecting Wi-Fi:** source rules only match programs that bind the UE source IP. Added destination lookup/guard pairs so ordinary traffic to each private server selects the correct table and current preferred source.
- **Incorrect 5G detection:** ModemManager reported access technology as indexed `.value[n]` entries. The launcher now reads those arrays as well as scalar forms.
- **Incorrect gateway validation:** QMI bearer gateways such as `10.45.0.5` and `10.46.0.6` need not equal Spark service IPs. The launcher records gateway metadata and verifies the actual server route instead.
- **Malformed copied shell variables and job waits:** the self-contained Python launcher avoids fixed copied addresses and damaged `$UE1_PID`/`$?` wait expressions. Both processes start before either is waited on, and actual return codes are retained.

| Role | Private table | Source lookup / guard | Destination lookup / guard | Destination |
| --- | --- | --- | --- | --- |
| UE1 | 151 | 10151 / 10152 | 10153 / 10154 | `10.45.0.1/32` |
| UE2 | 152 | 10161 / 10162 | 10163 / 10164 | `10.46.0.1/32` |

Each table contains a host route to its server using the selected WWAN and actual UE source address. Lookup rules select the table; subsequent unreachable rules are intended to reject matching traffic if that table loses the server route. Ordinary and source-bound route lookups are both checked before UL. Guard behavior under deliberate route removal remains untested on hardware. The Wi-Fi default route remains available for other destinations.

### 3.7. Shutdown and evidence retention

The updated Laptop shutdown sequence is UE1 first, then UE2:

```bash
sudo python3 ~/falcon-reset-ue-network.py --ue 1 --shutdown
sudo python3 ~/falcon-reset-ue-network.py --ue 2 --shutdown
```

The helper reselects the current modem by IMEI, disconnects active PDU sessions, clears the role's host IPv4 state, deletes all listed modem bearers, disables the modem, and checks zero bearers, disabled state, and clean host configuration again. It preserves the other UE and management network. Failure or recreated state stops completion. Live execution of this shutdown path on the Laptop was **Not run** during this log preparation; offline tests passed. The updated embedded helper must be installed on the Laptop before using the new option. Modem disable does not physically remove USB or external power.

Traffic should finish and the finite xApp should delete both subscriptions normally before modem/RAN shutdown. The raw full Laptop logs remain on the Laptop; normalized operator input, both KPM logs, parsed rows, selected CU identities, DU startup logs, PHY summaries, analysis code, and PNG/SVG plots are retained in the repository.
