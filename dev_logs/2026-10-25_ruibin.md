## 3. Technical Details and Decisions

### 3.1. Integrated RF and identity baseline

The final runtime combined Falcon `main`, OCUDU `falcon-dev` and FlexRIC `main`.
FlexRIC retained commit `3597413f`, originally dated October 24; the day’s
integration did not create a new KPM SDK ABI or implement the application broker.
Falcon and OCUDU merges retained the existing Dual UE network/automation and
CU identity behavior rather than replacing that application framework.

The RF wire names became `PUSCH.RSRP.dBFS` and `PUSCH.SNR.dB`. RSRP retained
software PUSCH DM-RS power in dBFS, and the SNR-named field retained the selected
PHY SINR estimate in dB. Valid zero, signed REAL values and missing samples
remained distinct. The first renamed UE1 run produced 63 seven-metric reports,
including 47 numeric RF samples and 16 unavailable RF samples, with no collector
drops and normal cleanup. Its missing CU feed meant that run verified RF
reception, not IP binding.

### 3.2. 100 ms source windows and scope-aware association

- DU scheduler/RLC source configuration and DU KPM subscription used 100 ms;
  CU identity remained 1000 ms, Core polling 1 second and source freshness 3 seconds.
- The CU allocation `du36-cuue28-v1` placed the 36-bit serving DU ID above the
  28-bit CU UE index in the optional eight-octet RAN UE identity. The mapper
  associated `(PLMN, gNB, DU ID, F1AP ID)` with CU/Core identity before obtaining
  the active session/IP. Equal F1AP ID 1 on DU1 and DU2 therefore remained distinct.
- This explicit allocation was an admitted project contract. The CU UE index
  did not prove a shared lifecycle generation; same-DU context reuse retained
  conservative handling.
- The isolated SCTP comparison showed repeated gaps up to 208.088 ms with
  `NODELAY` off. With it on, receive intervals ranged from 99.854 to 100.188 ms.
  Later live captures established the complete pipeline behavior.
- A temporary snapshot-concurrency change was not retained. The final provider
  cache/cleanup and collection/executor behavior remained deferred by operator
  request; regular arrival spacing did not establish atomic source snapshots.

### 3.3. Expanded metric contract and implementation

The 27-measurement profile retained the seven baseline names and added CQI,
DL/UL MCS, PHR, BSR, DL buffer occupancy, DL/UL MAC throughput, HARQ/CRC outcomes
and REAL DL/UL PRB percentages. Six companion fields carried CQI/MCS sample
counts and the latest PHR/BSR/DL-buffer indication ages. The complete field,
unit, console-column and aggregation mapping is in the
[standalone reference](../docs/du_kpm_metrics_reference.md).

CQI and MCS were rounded window means; PUSCH RF fields were means of available
dB samples. PHR, BSR and DL buffer retained latest-indication values with ages,
rather than fabricating a fresh measurement every 100 ms. Negative PHR and
negative SNR remained valid. CQI and PRB getters resolved actual sparse UE
indices instead of treating a vector offset as identity.

PRB utilization used `100 × used_PRB_slots / (directional_slots × cell_PRBs)`.
Multiplication preceded division. Legacy fields retained INTEGER percentages;
`PRB.UsageDl.Percent` and `PRB.UsageUl.Percent` retained fractional REAL values.
The xApp separately derived `100 × NOK / (OK + NOK)` for DL HARQ and UL CRC,
with no value for a zero denominator. These ratios were outside the 27 raw
measurements and described radio outcomes, not IP packet loss.

The collector preserved unsigned byte/count values, including the synthetic
4294967295-byte boundary. The accepted seven profile remained the launcher
default, five remained available as fallback, and `--du-metrics 27` explicitly
selected the expanded capture. The native DU and isolated collector/plugin were
rebuilt. Existing CU/SDK behavior was reused for the metric expansion itself.

### 3.4. Repeatable workload and diagnostics

an overall 335-second budget. It checked current identity, allocation and routes
around phases, retained failed phases rather than silently passing them, and
handled only its owned iperf children on interruption. Both reconnect watchers
and UEs remained running after the finite workload completed.

Spark section 7b used a 360-second xApp capture. Laptop commands remained in
the reconnect Quick Start, with longer explanations in the archived reference.
Both iperf servers gained UTC timestamps, one-second intervals, flushed output
and separate logs. The DU1/DU2 debug wrappers retained role-specific config,
binary hash and console timing; a fatal signal triggered bounded thread stacks
and register/instruction capture. GDB changed execution timing and did not
constitute a fix for the earlier crash.

### 3.6. Reporting and interpretation

Produced the English report and seven PNG/SVG figure pairs, including all 27
metric line charts. The UL overview order was FR1 UL, FR3 UL, SNR, RSRP, NOK,
PHR, MCS, PRB and BSR. A separate DL overview showed MAC rate, CQI, MCS,
REAL PRB, buffer occupancy, RLC SDU delay and HARQ NOK percentage.

Colored solid throughput curves represented one-second DU UL MAC averages;
black dashed curves represented iperf receiver goodput. Different protocol
layers and interval boundaries explained why exact equality was not expected.
The independent 27-metric table was moved to `docs/du_kpm_metrics_reference.md`
and the report retained a link to it.

RSRP 0 dBFS was accepted as a normal upper-bound reading, retained in plots
and statistics rather than classified as an anomaly. Missing RF remained
`no_value`. PRB had no negative values. Negative PHR represented UE power
headroom in dB and did not directly establish insufficient DU gain. Latest
PHR/BSR/buffer values retained their freshness semantics.
