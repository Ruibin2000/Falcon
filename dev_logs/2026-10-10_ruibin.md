## 3. Technical Details and Decisions

- **Original defect:** the RSRP/RSRQ getters were placeholder implementations
  using a real SNR field under incorrect measurement names. Both selected
  `last_ue_metrics[0]`, cast its value to an integer, and returned one record
  without mapping the requested UE list. Calling these dummy implementations
  was consistent with their incorrect semantics; they were not simply fixed
  synthetic constants.
- **Underlying data already existed:** the scheduler accumulated
  `crc_pdu.ul_sinr_dB` into its PUSCH SNR statistics and exported the window mean
  through `pusch_snr_db`. The missing component was correct KPM exposure in the
  current DU provider, rather than the entire PHY/scheduler measurement path.
- **Prepared cumulative patch:** the OCUDU patch replaced the placeholder
  registrations with `FALCON.PUSCH.RSRP.dBFS` and `FALCON.PUSCH.SNR.dB`, added
  `get_snr`, and removed the incorrect RSRQ getter. Its proposed implementation
  mapped F1AP UE identifiers to scheduler snapshots, used `REAL` records,
  preserved request order, and emitted `noValue` for unavailable measurements.
  A new `nof_pusch_snr_reports` snapshot field distinguished measured `0 dB`
  from a window with no samples. These were patch contents, not deployed behavior.
- **Measurement semantics:** RSRP used uplink PUSCH DM-RS power in software
  dBFS. SNR retained the legacy field name while exposing the PHY-selected
  `ul_sinr_dB` value in dB. The package did not add a separately named SINR
  metric or measured RSRQ; the xApp's `RSRQ = n/a` was a local capability notice.
- **Integration package:** the configuration requested the existing five DU
  measurements plus the two RF metrics at 1000 ms. Cumulative RF patches
  replaced the historical RSRP-only patches and were not intended to be stacked
  with them. FlexRIC required the existing timestamp repair first.
- **Current source state:** OCUDU was pinned to
  `050a2bb72e1d794cd60570d809987c1fcda3e54b`; its five RF-patch target files had
  no differences from `HEAD`. FlexRIC was pinned to
  `736508123fe4b5dc3db83fb5baf5f0a8e9b04fe8`; its monitor diff contained only
  the existing timestamp display repair, with neither custom RF metric name.
  Thus, "code not modified" was accurate for applying this RF package, while
  patch/test/configuration files already contained proposed implementation work.
- **Repository state and reporting date:** RF patch, configuration, script,
  and test artifacts were untracked; the bring-up document was modified. Its
  RF extension section was dated 2026-10-09. This log recorded today's reported
  progress and audit without attributing every existing artifact to today.
